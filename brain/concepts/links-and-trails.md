# Links and trails

**Read this before writing either.** Bush names two things, and MEMEX has two
things. Confusing them is what leaves a Library with hundreds of ties, one
route, and nothing anyone can walk.

Bush names four operations in §7. Three of them are these; the fourth is search.

> SEARCH  — "What information matches this query?"
> INDEX   — "Where is this information stored?"
> LINK    — "What other item is related to this?"
> TRAIL   — "What path through knowledge is useful?"

---

## Link

**A tie between two Books.** Written as a double-bracketed slug anywhere in a
Book's text.

- Answers: *what other item is related to this?*
- Made **freely**. There is no bar, no permission, no ceremony.
- Symmetric in meaning, one-directional in text: A links B; B need not link A.
- A link asserts relatedness. It asserts **no order and no reason**.

Bush §7: *"The process of tying two items together is the important thing."*
A link is that act, and nothing more.

---

## Trail

**The logical route between Books, and the logical flow itself.** An ordered
path where each step names what the step before it forced.

- Answers: *what path through knowledge is useful?*
- Lives in `trails/<name>.md`. **Never inside a Book** — a route that lives in
  one Book cannot pass through another, so it would not be a route.
- Each step carries: the move, a date, and **why that turn was taken**.
- **Order is logical, not chronological.** Dates ride along; they do not decide
  the sequence. A trail whose steps run 05-31 → 05-25 → 05-16 → 07-14 is correct
  when the reasoning runs that way. A trail ordered by date is a chronology
  wearing a trail's clothes.
- A step's reason is **never invented**. Recovered trails take their reasons from
  the dated entries already in the Books; where the record holds none, the step
  is dropped rather than guessed.
- Steps are append-only. A wrong step is answered by a later one.

A trail needs **no question and no Learned line.** Requiring one of every route
is why, for a long time, there was only ever one.

---

## Where `## See Also` fits

A Book's `## See Also` is **links, not a trail.** It is the layer below.

Measured in the Library this system was built for:

| | count | carries |
|---|---|---|
| links inline in prose | 164 | context from the sentence around them |
| links in `## See Also` | 119 | relatedness and nothing else |
| ties any trail explains | 65 of 209 | a reason, and a position in a route |

**68% of ties had no reason recorded anywhere.** That is not a defect; it is the
raw material. You tie two things before you know why — which is exactly why Bush
keeps LINK and TRAIL as separate operations.

The parallel to the other half of MEMEX is exact:

| | claims | associations |
|---|---|---|
| cheap, no reason needed | `state/candidates.jsonl` (outside the Library) | inline links, `## See Also` |
| deliberate and reasoned | the curated facts | a trail step |
| the promotion | candidate → the owner's yes → fact | **link → trail step** |

`memex trail --unexplained` counts the ties nobody has reasoned about. It is a
better measure of what is left than counting Books, because a Book can sit on a
route while its own links stay unexplained.

## Why a trail exists at all

In the owner's words:

> "What really matters, the reason we are making the trail, is to record the
> association and logical relationships between knowledges (books). This can be
> shared or be used as a clue for other agent or the same agent at different
> time. **This is all we need. Nothing else.**"

So a trail carries four things and no more:

| | |
|---|---|
| a name | so a reader knows which route this is |
| ordered steps | the logical flow — each names what the one before it forced |
| a link on each step | the association — which Books the step ties |
| a date per step | the timemark |

**Deliberately cut:** `Status`, `Question`, `## Learned`, `## Open`, and an
agreed/observed mark on steps. They are lifecycle and conclusions, not
associations, and a trail that demands them is a trail nobody writes. There was
also briefly a second shelf for "Inquiries" — a tier Bush does not have. An open
trail was all that ever meant.

Add back only what proves necessary. Simple first.

## Where a Book fits

A Book holds **what is known**. It never holds a route. It is *reached* by
routes, and its `## Trails through this Book` section lists which ones —
derived, regenerated by `memex trail --sync`, safe to rewrite because nothing in
it lives only there.

Bush §7: *"any item can be joined into numerous trails."* The item stays where it
is; what changes is the path through it.

## Commands

```
memex trail                      every route, and the Books it crosses
memex trail <name>               walk one, in order, with reasons
memex trail --through <book>     which routes reach this Book
memex trail --suggest <book>     recover a candidate route from links + dates
memex trail --sync               rewrite every Book's back-references
memex trail --orphans            Books no route reaches
memex trail --unexplained        ties with no reason recorded anywhere
```

## The Button

Bush's memex ties two items together **when the researcher presses a button** —
§7, *"the process of tying two items together is the important thing."* Nothing
ties itself.

MEMEX keeps that literally. **The Button** is the moment the owner is shown one
exact sentence and one exact destination, and says yes:

    Should I write "<the sentence, as it will appear>" on <shelf/book>?
        Yes · Reword · Different Book · No

It names the moment, not the widget — today it is a question in a terminal; it
will be something else later and the name still holds.

**Nothing enters a Book except through the Button.** Not the Scribe, which is
refused in code; not an agent that judged the fact obviously true. Three things
may press it: the owner (the `memex-input` skill), the agent the moment it
notices something, and the **Stop hook**, which will not let a turn end while
something queued has gone unasked.

There are two Buttons, because there are two acts. A **FACT** Button offers a
sentence and a destination. A **TIE** Button offers a Book and the route it would
join, with the reason quoted from what is already written. Ties are asked first:
a fact with no route is in the Library but on nobody's path.

What Bush got for free from a physical button — a human deciding, every time —
has to be stated here, because this agent can write on its own.
